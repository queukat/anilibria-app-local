3) Episode update time bug ("застыло")
Симптом
- На карточках релизов/серий отображалось "Обновлен X назад", но при длительном нахождении на экране текст мог оставаться старым без естественного роста времени.

Root cause
- Тип: C (timestamp корректный, но UI не пересчитывал relative-time).
- Подтверждение по коду:
  - Формирование текста происходило заранее при маппинге карточек: app-tv/src/main/java/ru/radiationx/anilibria/common/CardsDataConverter.kt (toCard для Release/Youtube).
  - Кэш карточек хранится в памяти ViewModel как готовые LibriaCard: app-tv/src/main/java/ru/radiationx/anilibria/common/BaseCardsViewModel.kt (currentCards/_cardsData).
  - На главном экране описание ставилось по item.description и не имело периодического ticker: app-tv/src/main/java/ru/radiationx/anilibria/screen/main/MainFragment.kt (onItemSelected).

Что изменено
- Commit: ab5004f2
- Файлы:
  - app-tv/src/main/java/ru/radiationx/anilibria/common/LibriaCard.kt
  - app-tv/src/main/java/ru/radiationx/anilibria/common/CardsDataConverter.kt
  - app-tv/src/main/java/ru/radiationx/anilibria/screen/main/MainFragment.kt
- Суть:
  - В LibriaCard добавлен явный источник истины для relative-time: relativeTimestampSec (+ relativePrefix).
  - Добавлен resolveDescription(context), который пересчитывает относительное время в момент отображения.
  - В MainFragment добавлен ticker 60s (только пока экран активен), который переустанавливает описание для текущего выбранного item.

ACCEPTANCE CRITERIA check
- В коде есть явный источник истины (timestamp): да, LibriaCard.relativeTimestampSec + исходный Release.torrentUpdate.
- Нет persistence готовой строки relative-time: да, в persistence по-прежнему timestamp/доменное время; готовая строка вычисляется в UI.
- Повторное открытие экрана дает актуальный текст: да, описание рендерится через resolveDescription(context).
- Долгое открытие экрана не замораживает текст: да, ticker в MainFragment обновляет подпись раз в 60 секунд.

Как проверить вручную (без тестов)
1. Открыть главный экран и выбрать карточку релиза с "Обновлен ...".
2. Зафиксировать текст (например, "Обновлен 2 часа назад").
3. Оставить экран активным >60 секунд (лучше 2-3 минуты).
4. Убедиться, что текст изменился (например, минуты/часы обновились) без перезапуска экрана.
5. Вернуться назад/вперед на главный экран и проверить, что relative-time не возвращается к старому значению.

Риски/что могло сломаться
- resolveDescription использует префиксный replace по relativePrefix; для нестандартного description с таким же префиксом может получиться лишняя склейка текста.
- Тикер обновляет description каждые 60с (минимальная постоянная активность coroutine на экране Main).
