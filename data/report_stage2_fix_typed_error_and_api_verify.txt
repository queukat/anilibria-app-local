2) Part 1 (before/after)

A-B-C. Replaced fail-closed IllegalStateException with typed domain error
Before:
- AuthTokenStorage.saveToken() in fail-closed path raised IllegalStateException with text message.

After:
- Added typed domain hierarchy:
  - CriticalSecureStorageException (sealed RuntimeException)
  - CriticalSecureStorageUnavailableException(cause)
- AuthTokenStorage.saveToken() now throws CriticalSecureStorageUnavailableException in unavailable secure storage mode.
- Original crypto init failure cause is propagated through CriticalSecureStorageStatus -> exception.cause.

C. Fail-closed behavior / plaintext safety
Before:
- unavailable secure storage path relied on generic exception type.

After:
- saveToken(): never writes plaintext in unavailable mode, clears plaintext key, then throws typed exception.
- getToken(): returns null when secure storage unavailable (no side-effects in read path).
- migration plaintext->encrypted:
  - if encrypted is available: migrate key to encrypted and clear plaintext.
  - if encrypted is unavailable: plaintext key is cleared and not used for reads.

D. app-tv UX safety (no uncaught crash)
Before:
- auth VMs mapped failure to generic error.message.

After:
- Added explicit typed error mapping in app-tv:
  - mapAuthErrorMessage(CriticalSecureStorageUnavailableException) -> user-friendly RU message.
- AuthCredentialsViewModel and AuthOtpViewModel now use typed mapper.
- Typed secure storage failure no longer depends on raw exception text and is handled as known UX case.

E. Tests
- data/AuthTokenStorageTest:
  - verifies unavailable path throws CriticalSecureStorageUnavailableException.
  - verifies plaintext token is not used in unavailable mode.
  - verifies unavailable cause propagation into typed exception.
- app-tv/AuthCredentialsViewModelTest:
  - verifies VM handles typed secure storage exception without crashing.
  - verifies expected user message is emitted and guided chain is not finished.
